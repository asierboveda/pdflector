# Repository Audit — PDFLector (`origin/main` @ `fb2cc5c`)

**What this repo does:** PDFLector is a Rust + Kotlin PDF reader and stylus note-taking app for Android tablets (`crates/pdf_core`, `crates/pdf_android`, `android/product`), plus a desktop preview crate (`crates/pdf_app`) and benchmarks (`crates/pdf_bench`). Assumed load: a single student or researcher on an 8 GB Android 16 120 Hz stylus tablet (TCL NXTPaper 11 Plus, `1440×2200`) reading 1–500 page PDFs with stylus ink, highlights, offline folder sync, and optional Gemini AI study queries.

---

## Must fix

### 1. Android cloud backup copies `gemini_api_key` off-device (`android/product/app/src/main/AndroidManifest.xml:6-8`)
- **What this is:** The `<application>` manifest declaration controlling Android Auto Backup and device-to-device transfer.
- **Problem:** `android:allowBackup` defaults to `true` with no `android:fullBackupContent` or `android:dataExtractionRules`. Android backs up `files/gemini_api_key` to Google Drive and transfers it to other devices, directly contradicting the UI prompt (`"Se guarda solo en este dispositivo"`).
- **Fix:** Add `res/xml/backup_rules.xml` and `res/xml/data_extraction_rules.xml` excluding `<exclude domain="file" path="gemini_api_key"/>` (keeping `notebooks.json` backed up), wire both in `AndroidManifest.xml`, and lock them with a JVM XML unit test.
- **If we skip it:** Every user's private Gemini API key leaves the tablet in cloud backups and device transfers.

### 2. Permission TOCTOU on `gemini_api_key` + `AlreadyExists` unlink bug (`crates/pdf_android/src/gemini_key.rs:133-138`, `crates/pdf_core/src/fsutil.rs:30-42`)
- **What this is:** Atomic secret file writer for the user's Gemini API key and its shared atomic-write helper in `pdf_core`.
- **Problem:** `save_key` writes the plaintext key through `write_atomic` using the process default umask (`0644`), renames it into place, and only calls `set_permissions(0o600)` afterward (TOCTOU window). Separately, `fsutil::write_atomic_with` (`fsutil.rs:40-42`) unconditionally calls `fs::remove_file(&temp)` on any error, deleting a pre-existing file if `create_new(true)` failed with `AlreadyExists`.
- **Fix:** Add `write_atomic_private` (setting `OpenOptionsExt::mode(0o600)` on Unix before creating the temp file), call it from `save_key`, and only unlink `temp` in `fsutil.rs` if `open(&temp)` actually created it.
- **If we skip it:** Plaintext keys briefly exist world-readable on disk, and a colliding temp path gets deleted on error.

### 3. JNI `DeleteLocalRef` on cached global ref + missing `exception_clear()` (`crates/pdf_android/src/jni/ime.rs:148,178,200,237`)
- **What this is:** JNI wrappers bridging Rust to `ImeHelper` for search, note, and Gemini-key text input.
- **Problem:** All four functions wrap the cached `Global<JObject>` raw pointer with `unsafe { JClass::from_raw(env, raw) }`, creating an *owned* local handle that calls `DeleteLocalRef` on a global ref at scope exit (immediate CheckJNI abort / undefined behavior). `ime_attach`, `ime_hide`, and `ime_set_text` also drop errors without calling `env.exception_clear()`.
- **Fix:** Borrow the cached pointer with `unsafe { env.as_cast_raw::<JClass>(&raw)? }` (matching `activity` two lines below) and clear pending exceptions on error in all four helpers.
- **If we skip it:** Any CheckJNI / debug ART run aborts on the first keyboard open, and a Java exception poisons subsequent JNI calls on the render thread.

### 4. JNI pending exception before `setAttributes` + null `getInsetsController()` crash (`crates/pdf_android/src/jni/window.rs:101-126,154-173`)
- **What this is:** Window setup calls enabling 120 Hz display mode and immersive full-screen bars.
- **Problem:** `enable_120hz` ignores errors from `env.set_field` (`let _ = ...`) without calling `env.exception_clear()` before calling `setAttributes` (fatal JNI error if a field throws on an OEM ROM). `enter_immersive` calls `controller.hide(...)` without checking `controller.is_null()` or clearing exceptions — `Window.getInsetsController()` does not exist on API 29 (the app's `minSdk = 29`) and can return null before attach.
- **Fix:** Clear exceptions after optional `set_field` calls and check `controller.is_null()` + clear exceptions on failure in `enter_immersive`.
- **If we skip it:** Instant crash on Android 10 (API 29) devices and on any ROM where `LayoutParams` fields throw.

### 5. `ACTION_VIEW` overwrites user `state.json` with defaults & ignores saved reading mode (`crates/pdf_android/src/reader/life.rs:211-238`)
- **What this is:** Startup branch handling "Open with" PDF intents (`LaunchRequest::File`).
- **Problem:** Live-reproduced on TCL 9469X (`tcl_ux_10_landscape.png`): opening a PDF via `ACTION_VIEW` never calls `load_state()` or `load_progress()`, opens in `Tap` mode at page 0 with `DefaultLight`, and immediately calls `reader.save_state()`, overwriting the user's saved theme, library layout, and grid columns in `state.json` with defaults.
- **Fix:** Restore `load_state` + `load_progress` before opening `LaunchRequest::File`, apply the document's persisted `page`, `reading_mode`, and `scroll_frac`, and only then save state.
- **If we skip it:** Opening any PDF from a file manager wipes the user's theme, layout preferences, and Continuo position.

### 6. Document & fling state leaks across Library/Viewer transitions and Pause (`crates/pdf_android/src/reader/library.rs:47-96`, `crates/pdf_android/src/reader/navigation.rs:325-380`, `crates/pdf_android/src/lib.rs:599-606`)
- **What this is:** Teardown paths when returning to Library, switching PDFs, or backgrounding the app.
- **Problem:** `enter_library()` never drops `self.doc`, stops `scroll_fling`, or clears `page_geometry_cache`, `scroll_geoms`, `render_failures`, or `annotations` (measured on TCL 9469X: `+79.3 MiB` PSS retained after 8 Library↔Viewer roundtrips). `open_pdf_at()` never clears `page_geometry_cache` (previous PDF's page sizes leak into the new PDF until first render) or stops active fling. `MainEvent::Pause` leaves `scroll_fling` and `tool_gesture` running even though `PdfLectorActivity.onPause()` cancels ink.
- **Fix:** Clear `doc`, `page_geometry_cache`, `scroll_geoms`, `render_failures`, `annotations`, and active fling in `enter_library`; clear `page_geometry_cache` + fling in `open_pdf_at`; cancel fling + `tool_gesture` on `MainEvent::Pause`.
- **If we skip it:** Memory climbs across document switches, mixed-size layouts glitch with the previous book's dimensions, and pausing mid-stroke desyncs native state from AndroidX ink.

### 7. Wet-ink capsule emits `NaN`/`Infinity` GL vertices on non-finite coordinates (`android/product/app/src/main/kotlin/com/pdflector/app/ink/InkStrokeGeometry.kt:68-77`)
- **What this is:** Pure-Kotlin GPU triangle tessellator for low-latency stylus wet ink.
- **Problem:** `capsule()` validates `widthPx` for finiteness, but not `x0/y0/x1/y1`. If any coordinate is `NaN` or `Infinity`, `!(length > 1e-3f)` evaluates to `true` and falls into `fan(...)`, writing `NaN` vertex coordinates into the GLES buffer instead of returning `0`.
- **Fix:** Guard `if (!x0.isFinite() || !y0.isFinite() || !x1.isFinite() || !y1.isFinite()) return 0` at the top of `capsule()`.
- **If we skip it:** One bad stylus event poisons the GLES vertex array for the stroke.

### 8. Redundant native swap on wet-ink pen-down (`crates/pdf_android/src/reader/tools.rs:291-298`)
- **What this is:** Stylus pen-down handler (`begin_tool_gesture`) that dispatches to AndroidX front-buffered wet ink.
- **Problem:** Even when `self.ink_overlay` accepts the pen-down dot (`!requires_native_wet()`), line 297 unconditionally calls `self.mark_repaint()`, forcing a full native GLES swap on every pen-down (regressing PR #55's front-buffer isolation).
- **Fix:** Only call `self.mark_repaint()` when `tool != ToolKind::Ink || self.requires_native_wet()`.
- **If we skip it:** Every stylus stroke pays an unnecessary full-screen EGL swap on touchdown, adding pen-down latency and contention with the AndroidX front buffer.

### 9. Bottom chrome bar freezes on stale page number after page turn (`crates/pdf_android/src/reader/navigation.rs:88-89`)
- **What this is:** Page-turn overlay invalidation inside `goto_page()`.
- **Problem:** Live-reproduced 3× on TCL 9469X (`tcl_ux_08c`, `tcl_ux_08f`, `tcl_ux_09`): turning pages while viewer chrome is visible clears `page_badge` and `sheet_bitmap` but never clears `chrome_bottom_bitmap`. The bottom scrub bar stays stuck on the previous page (`Pág. 4 de 80` while Page 5 is displayed).
- **Fix:** Set `self.chrome_bottom_bitmap = None;` next to `self.page_badge = None;` in `goto_page()` (and wherever `self.page` changes in scroll sync).
- **If we skip it:** Users tapping next/prev with toolbars visible see the wrong page number and scrubber position.

### 10. Plaintext Gemini API key lingers in Java static `ImeHelper.sText` (`crates/pdf_android/src/reader/study.rs:297-304`, `crates/pdf_android/src/reader/library.rs:907-929`)
- **What this is:** Study panel close / IME teardown paths after saving or canceling a Gemini key.
- **Problem:** `close_study()` and `lib_close_ime()` hide the keyboard without calling `ime_set_text(app, "")`, leaving the user's pasted Gemini API key inside Java's static `ImeHelper.sText` string until the next search or note overwrites it (and risking leaking it into the next opened editor due to async `attach()`).
- **Fix:** Call `crate::jni::ime_set_text(app, "")` when closing the key editor / study panel or hiding IME.
- **If we skip it:** A pasted API key stays resident in JVM static memory and can briefly populate the next search bar or note field.

## Should fix

### 11. Uncapped MuPDF `fz_store` causes 461.8 MB PSS spike on mixed PDFs (`crates/pdf_core/src/engine/mupdf.rs`, `crates/pdf_core/src/engine/display_list_cache.rs`)
- **What this is:** MuPDF rendering context and `PR-03` display-list cache (`24 MiB` / 16 pages).
- **Problem:** Measured on TCL 9469X during 30 Continuo swipes on `mixed_stress.pdf`: `dlcache` reports `0.56 MB` (`16 entries`), yet `Native Heap` jumps from `54.1 MB` → **`246.4 MB` (`+192.3 MB`)** and `TOTAL PSS` hits **`461.8 MB`** (2.3× over the 200 MB target) because MuPDF's default 256 MiB process-wide `fz_store` is never bounded or shrunk.
- **Fix:** Cap or periodically shrink MuPDF's internal store (e.g., `32–48 MiB` budget via `mupdf` store limit / shrink hook on eviction) and calibrate `dlcache` telemetry against actual RSS delta.
- **If we skip it:** Scrolling image-heavy textbooks risks Android LMK killing the app on 4–6 GB tablets and wastes >200 MB RAM on TCL 9469X.

### 12. `PageSlots` churns GL textures every scroll page → `+71–75 MB` `GL mtrack` & 120 Hz miss (`crates/pdf_android/src/gpu/textures.rs:273-283`, `crates/pdf_android/src/gpu/page_slots.rs:43-53`)
- **What this is:** Continuo mode's 4-slot GPU page texture cache.
- **Problem:** Measured on TCL 9469X: `GL mtrack` jumps `+71.3 MB` (`56.4 → 127.7 MB`) on `mixed_stress.pdf` and reaches `131.3 MB` on `large_document.pdf`, while `frame p95` lands at **`11.8–14.6 ms`** (missing the `8.33 ms` 120 Hz budget by 42–75%). Every new page calls `glGenTextures` + `glTexImage2D` (~10.7 MB) + `glDeleteTextures` + `info!()` log on the render thread, triggering deferred DMA-BUF retention in Mali-G57 MC2 and synchronous upload stalls.
- **Fix:** Pre-allocate 4 reusable GL texture handles (`glTexSubImage2D` when dimensions match, in-place `glTexImage2D` otherwise), remove per-texture `info!()` logging from the hot loop, and upload via PBO or incremental band uploads.
- **If we skip it:** Continuo scrolling cannot hit 120 Hz (`< 8.33 ms`) and Graphics RAM stays >165 MB.

### 13. Cold startup destroys & recreates EGLSurface + Dual FBOs 3× (`crates/pdf_android/src/gpu/surface.rs`, `crates/pdf_android/src/lib.rs`)
- **What this is:** Surface initialization and `WindowResized` handler during app launch.
- **Problem:** Measured on TCL 9469X: cold launch takes **`649 ms` median** (`633–759 ms`). Logcat shows `EGLSurface` and Dual FBOs (`1440×2200`, 25.3 MB) are torn down and recreated **3 times** at identical dimensions, and `library.json` is parsed twice before the first frame.
- **Fix:** Skip `recreate_surface` when `has_surface()` and `(width, height)` are unchanged; deduplicate initial `load_progress()` call.
- **If we skip it:** Every cold start pays ~150–200 ms of wasted GPU allocation and duplicate disk reads.

### 14. CPU `scale_bitmap` is 5× slower than MuPDF re-render on ARM64 (`crates/pdf_core/src/bitmap.rs` / `crates/pdf_bench`)
- **What this is:** CPU bitmap upscaler used as a zoom preview while MuPDF re-renders.
- **Problem:** Measured on TCL 9469X (`pdf_bench` 5-run median): `scale2x` = **`71.9 ms`** vs `rerender1` = `14.7 ms`; `scale4x` = **`285.3 ms`** vs `rerender2` = `55.0 ms`. Scaling on CPU takes 5× longer than letting MuPDF draw the crisp page, while the GPU already bilinear-scales textures for free.
- **Fix:** Drop CPU `scale_bitmap` from the interactive zoom path (rely on GPU bilinear quad scaling until MuPDF crisp re-render arrives) and delete unused CPU scaling helpers if unreferenced outside benches.
- **If we skip it:** Any caller invoking CPU zoom preview freezes for 72–285 ms.

### 15. Duplicated atomic JSON writers, raw `fs::write` on `classes.dex`, and wall-clock test (`crates/pdf_android/src/jni/ime.rs:57`, `crates/pdf_android/src/folder_sync.rs:752,1233-1254`, `crates/pdf_core/src/folder_sync.rs:1130`)
- **What this is:** Persistence helpers across `pdf_core` and `pdf_android`, plus `ImeHelper` DEX extraction.
- **Problem:** Two duplicate atomic JSON writers remain after `CO-02` (`pdf_android/folder_sync.rs:752`, `pdf_core/folder_sync.rs:1130`). Five call sites still use non-atomic `fs::write` — critically `jni/ime.rs:57` writes `classes.dex` directly, so a mid-write crash leaves a corrupt DEX on disk permanently disabling keyboard input. Also `folder_sync.rs:1233-1254` still uses wall-clock `Instant::now()` in a test.
- **Fix:** Delete both duplicate helpers in favor of `pdf_core::fsutil::write_atomic`, switch `jni/ime.rs:57` (and `launch.rs:255`, `library.rs:834,980`, `discover.rs:177`) to `write_atomic`, and inject a deterministic clock in the test.
- **If we skip it:** Duplicate I/O logic drifts and a crash during first-run DEX extraction breaks IME until app data is wiped.

### 16. `ci.yml` misses `pdf_app` tests and host `pdf_android` clippy (`.github/workflows/ci.yml`)
- **What this is:** GitHub Actions CI workflow gating PR merges.
- **Problem:** CI never runs `cargo test -p pdf_app` or `cargo clippy -p pdf_android --lib --tests -- -D warnings`, allowing host-side regressions in desktop/test-only `pdf_android` code to slip past PR checks.
- **Fix:** Add both commands to the existing Rust CI job (~4 lines).
- **If we skip it:** Broken `pdf_app` tests or `pdf_android` host clippy warnings reach `main`.

**Verdict:** Solid TDD discipline across all 15 cards, but 10 Must-Fix security/JNI/state bugs and two large memory/GPU bottlenecks (`461.8 MB` PSS and `14.6 ms` `p95` frame time on TCL 9469X) must be resolved before calling the tablet experience production-ready.

**Lean:** `-160` lines (dead `lib_org_chips`, duplicate atomic JSON writers, redundant CPU zoom scale), `-0` dependencies possible.

**Not checked:** Physical TCL T-Pen stylus feel / wet→dry pen-lift seam / palm rejection (`IN-01`); live Gemini HTTPS network calls with a real API key; live `folder_sync` scan against personal synced folders (excluded by D3 privacy rule); Android 10 (API 29) physical hardware; `crates/pdf_app` interactive desktop GUI runtime.
